# Decisions

Standing decisions are in docs/factory/BATCH1_PLAN.md (Mongo instead of Postgres, Better Auth, Stripe first, Mailer interface, Vercel-first, keep 3 deployments).

## Straightpin decisions (Phase 0, 5 Nov 2026)
- **D-001 Storage:** jobs store an excerpt (≤ 600 chars) plus link, not full HTML. Matches the brief's "short excerpt and link to employer", and keeps 250K jobs near 500 MB. M10 upgrade is a manual step.
- **D-002 Scheduler:** Cloudflare Worker cron calls `/api/cron/*` (CRON_SECRET); Vercel Cron only as daily backstop.
- **D-003 Design overrides of the landing-page-design skill:** two families plus mono and a margin note font, warm dark palette, no gradient on hero text, solid top bar, UI word "open" instead of "unlock". Reasons in docs/DESIGN.md section 7.
- **D-004 Classifier:** pure TypeScript inference from JSON weights (no ONNX on Vercel), same `AgencyModel` interface so ONNX can return on the VPS. Model only goes live past the precision gate; rules + review queue ship regardless.
- **D-005 Payments:** Stripe, not Paddle (owner rule). Brief's "Paddle overlay" becomes Stripe Checkout.
- **D-006 Auth:** Better Auth email code/magic link + passkeys, instead of Auth.js (kit decision).
- **D-007 Weight rule:** display uses Bricolage 600/700 (no 800) to respect the "no ultra bold" skill rule.
- **D-008 Competitor note:** DirectRoles live hero is now indigo gradient (brief recorded blue). HiringCafe is behind a bot challenge and is not crawled or bypassed.
- **D-009 Palette and mono (orchestrator review, 5 Nov 2026):** primary changed from teal #0F5C55 to pushpin tomato #B8381C (warm paper neutrals, dark mode #FF8A6B on #1A1512) so Straightpin is distinct from the other green/teal BufferSol products and friendlier for a consumer audience. Margin notes use ballpoint blue #2A4B9B so red keeps one job. Mono is now tiny metadata only (source host, first posted date); Caveat only for the "Old posting" note. All pairs checked AA.

- M1-A (5 Nov 2026), plan model: `PlanId` = free | weekly | monthly | lifetime | plus; `Interval` = week | month | year | once. Lookup keys are `straightpin_<plan>_<interval>` (straightpin_weekly_week, straightpin_monthly_month, straightpin_lifetime_once, straightpin_plus_month, straightpin_plus_year). Plan order is the rank for `requirePlan`; Lifetime ranks between Monthly and Plus (core plan, no Plus features).
- M1-A, meters: `opens` (per UTC day, Free 5) and `saves` (running total, Free 10). "Unlimited" is `UNLIMITED = 1_000_000` (Infinity does not survive JSON).
- M1-A, Lifetime checkout: Stripe Checkout `mode: "payment"` with `metadata.mode=lifetime` and `metadata.lookup_key`; the existing `payment_intent.succeeded` webhook path grants it. The 1,000 buyer cap (`product.lifetimeCap`) is not enforced yet.
- M1-A, marketing/pricing page copy still carries kit sample text (form endpoint copy, Postslot name swapped to Straightpin by search only). M1-B replaces it. The pricing table renders five cards with the kit's interval toggle until then.
- M1-A, dark mode palette stays on the kit's `[data-theme=dark]` switch (no `prefers-color-scheme` rule added).
- M1-A, fonts: Bricolage Grotesque drives `heading-1..6` via `--font-display-family`; Caveat is exposed as `font-note` for the single Old posting note. Hero heading gradient tokens are both ink (solid, per DESIGN.md §7). Added role tokens brand-tint, highlight, marker. Layout themeColor updated to the board colours.

## M2 (5 Nov 2026)
- **D-010 Only the 8 fields are stored:** ingest keeps a job only if its title maps to one of the 8 fields (`src/lib/jobs/fields.ts`, deterministic keyword rules). Everything else is counted (`outsideFields`) and dropped. This is the "prioritise 8 fields" storage mitigation, and the taxonomy also supplies `level` and `schedule` for the quiz (derived from title and excerpt, not from the feeds).
- **D-011 Data model:** `employers` is the source list and holds crawl state (etag, next crawl, fail count, status active/dead/blocked); this replaces `companies` + `ats_boards` for now. `jobs._id` is a 20 char hash of (employer, external id). `postedAt` = company first published date, else first seen, and is the sort key; `firstPublishedAt` itself stays null when the company gives none. MinHash signatures are not stored (storage): near duplicates collapse inside one board crawl, repost counts come from `dedupeKey` history.
- **D-012 Leases:** `crawl_leases` rows `_id=app:employerId` with `until`; claimed by one atomic `findOneAndUpdate` (a lost insert race is E11000 = not acquired). A tick leases up to 6 due boards, runs 3 at a time, stops starting boards at 40 s (board fetch timeout 8 s), always releases leases, and writes a `source_runs` row. Boards missed by the budget stay due.
- **D-013 Robots/limiter state is per invocation for now:** `fetchPolite` gets in memory robots and host limiter stores each tick (robots.txt is refetched once per host per tick). The Mongo backed `robots_rules`/`host_state` stores are still to do; the seed list has distinct hosts per ATS so the risk is two overlapping ticks hitting one ATS API host.
- **D-014 Closing:** a job missing from a full board listing on 2 consecutive crawls closes; an empty listing never closes anything (treated as an outage). JSON-LD crawls are capped (40 URLs) so they only close jobs the crawler saw as expired or 404.
- **D-015 Agency:** rules only (`SEED_RULES`), no model. A hard rule hit (`yes`, score >= 0.65) hides the post and feeds the "We removed N" receipt; a soft hit alone is `pending` (0.35 to 0.65) and stays visible without the Direct tag, waiting for the M3 review queue.
- **D-016 Quiz and matches without JS:** the quiz is server rendered, one question per screen, every option is a submit button of a GET form with the earlier answers as hidden fields; the live count is the indexed count behind a 60 s per instance cache. Matches state lives in the URL; saving answers is an explicit POST to `/api/profile`. Match score is deterministic (base 60 + remote, pay, level, freshness, minus ghost score) and uses only the company's own date for freshness.
- **D-017 Meters:** opens are per (org, UTC day, job): re-opening the same job is free; over the limit rolls the counter back and records nothing. Saves are a running total, +1 on a new save and -1 on unsave. Both are keyed by the billing org id like every other meter.
- **D-018 Mail scopes:** `MailMessage.category` gains `digest` and `alerts`, so the kit's suppression list and one click unsubscribe work per mail type. Free users get the digest at 08:00 local (hourly run, `lastDigestAt` guard, tz defaults from the country answer); paid users get alerts at most hourly (over 20 new becomes a summary of 10). Saving the answers form with a type switched on lifts its unsubscribe.
- **D-019 Cron:** the Cloudflare worker runs `crawl-tick` every minute and `digest`, `alerts` in minute 0 of each hour (`HOURLY_JOBS`). Nothing is deployed; the worker config change takes effect on the next `wrangler deploy`.
- **D-020 Citations:** the four third party statistics were removed instead of linked because the brief has no URLs (D-M1B "cited by name only" is superseded).
- **D-021 Seed sources:** `src/lib/jobs/sources.json` is labelled seed data (13 well known public boards across the six ATS types). Names and slugs come from memory and were not verified live; boards that 404 go dead after 3 failures and show in `source_runs`.

## M3 (5 Nov 2026)
- **D-022 Lifetime cap:** `claimLifetime(orgId, cap)` is an atomic counter (`counters` doc `app:lifetime`, `findOneAndUpdate` with `n < cap` and upsert, so a full counter collides on `_id` = sold out) plus one `lifetime_claims` row per org (re-claiming is free). The slot is taken when the Checkout Session is created (session `expires_at` = 31 min), given back on session failure, on `checkout.session.expired` and on a full refund. The webhook also claims on `payment_intent.succeeded` and always grants: a buyer who paid is never turned away, the claim only keeps the count honest. Sold out returns 409 `lifetime_sold_out` and the paywall greys the option.
- **D-023 Refund:** one per Stripe customer, stored in `refunds` (`_id app:customerId`). The row is written before the Stripe call (so two taps cannot both refund) and removed only if Stripe fails. Self serve needs a paid plan and a succeeded, unrefunded charge not older than `product.refundDays`; admins skip the window but not the once rule. The refund is created with an idempotency key, then the plan turns off at once (Lifetime: entitlement off and slot freed; subscription: cancelled and recomputed); the `charge.refunded` webhook converges to the same state. Audit entry `billing.refunded` and a transactional email through the Mailer.
- **D-024 Cancel:** `cancel_at_period_end` through the Stripe API, entitlement recomputed from Stripe, plan stays on until the date. Two taps in `/account` (Cancel plan, then Yes, cancel my plan). Card changes and invoices go to the Customer Portal. `/account` is the consumer page; the kit's `/app/billing` still exists behind the app shell. Checkout and portal now return to `/account`.
- **D-025 Paywall:** `/paywall?reason=opens|saves|feature&from=/path` outside the marketing layout (own close button, 44 px). Options are built from `product.plans`, Monthly pre-selected, renewal sentence and the refund line sit above the fold, no timers and no pre-ticked extras. `from` is checked by `safeFrom` (same site paths only). The open route now sends an over-limit free user here instead of `?limit=opens`.
- **D-026 Renewal reminders:** cron `renewal-reminders`, hourly (worker `HOURLY_JOBS`). Weekly and monthly: from 3 days before the renewal; annual: on the UTC day of the renewal. Only `active` plans that are not cancelling. One per (org, renewal date) via `markReminder`, claimed before sending. New mail scope `renewals` so the one click unsubscribe is per type (same pattern as D-018).
- **D-027 Admin:** founder only (`ADMIN_EMAILS`), non-founders get 404 (pages through the layout, APIs through `requireAdmin`). Crawl health reads `employers` plus the last 200 `source_runs`; runs now store per board results (`boards`) so success rate is per source; older runs without it count as no data. Review queue lists open `pending` jobs; confirm = agency (job flag `yes`, score 1), reject = direct (flag `no`, score 0); each answer upserts one row in `labels` (latest wins) with the classifier input. `labelGate` trains on 80 percent of labels and evaluates the held out 20 percent with the existing `passesGate`; the model stays off until it passes (needs 300 labels). User lookup: by email, shows plan, refund state, suspended flag; suspend, lift, refund (all audited). A suspended org cannot start checkout or open jobs.
- **D-028 `/bot` and `/about/data`:** facts, a short excerpt (<= 600 chars from `EXCERPT_MAX`) and a link; removal by robots.txt token `StraightpinByBufferSolBot` or email to `support@buffersoltech.com` (48 h, brief). The O*NET credit named in the brief is not on `/about/data` because no O*NET data is used yet; add it with the skills dictionary (v1). The page does not claim a closed-job retention period because no purge job exists yet.
- **D-029 E2E outbox on `globalThis`:** the test outbox is shared through `globalThis.__kitOutbox`; route bundles can load `transports.ts` twice and the cached auth instance sent magic links into a different copy (found when `/account` was the first page hit).

## M4 (5 Nov 2026)
- **D-030 Seed sources:** `sources.json` grows to 64 entries (24 Greenhouse, 9 Lever, 10 Ashby, 5 Workable, 4 Recruitee, 4 Personio, 8 JSON-LD career sites). The brief names no specific employers, only the ATS types and that career sites include Workday/iCIMS/custom, so entries are well known public boards chosen from memory. Every entry is `"verified": false` and the file note says so; nothing is claimed as live-checked. The crawl health page shows an "unverified" tag.
- **D-031 Source health:** new status `disabled`. The daily `source-health` cron disables an active source after 5 crawls in a row failed (reads the last 300 `source_runs`; runs that did not include the board are skipped; a success resets the count). Robots blocks stay `blocked`, and the crawl's own `dead` (3 fails) stays. Admin `/admin/crawl` shows the reason and an Enable button (`/api/admin/sources`); enabling sets `healthResetAt` so old failures do not re-disable it at once.
- **D-032 Alert rules:** instant alerts are saved rules (`alert_rules`: field, country, free text location, hourly pay floor), limited per plan by `alertLimit` in `product.ts` (Free 0, Weekly 3, Monthly 5, Lifetime 5, Plus 15; owner can retune). Free users keep the daily digest. The hourly cron sends one email per rule at most once an hour; after a downgrade the oldest rules within the limit keep working. An account with no saved rules and the old quiz `alerts` flag on keeps one alert from its quiz answers (back compat). Location is a case insensitive substring match on the job's place or region (`JobQuery.locationTerms`).
- **D-033 Manage without login:** every digest and alert email has "Change or delete your alerts" (`/alerts/manage?e&t`), a link signed with HMAC of the lowercased email under a key derived separately from the unsubscribe tokens, so neither link type can stand in for the other. It lists rules by email, pauses or deletes them, and stops all alerts or the digest. The link is a bearer credential; the page says not to forward the email. `/alerts` is in robots disallow.
- **D-034 Retention:** closed jobs are deleted 90 days after they closed, crawl records after 30 days (`RETENTION` in `jobs/retention.ts`; ARCHITECTURE.md said 180 days for closed jobs, superseded). `/about/data` prints these numbers from the same constants and a test fails if the page hand types a number. Daily cron `retention` (worker `DAILY_JOBS`, 03:00 UTC) also removes purged jobs from saved lists. The `source_runs` Mongo TTL reads the same constant as a backstop. Account export now includes alert rules and deletion removes them. Account deletion remains immediate, which is inside the "within 30 days" privacy claim.
- **D-035 Programmatic pages:** `/jobs/<field>/<location>` for the 8 fields x 33 places (3 countries, remote, 29 cities). A page exists only with at least 8 open non agency jobs (`MIN_JOBS_FOR_PAGE`); otherwise 404 and no sitemap entry. Intros are built from the rows (counts, top employers, pay range in the dominant currency, remote/hybrid split, newest age, old posting count); wording and paragraph order vary by a hash of the slug, and a sentence is dropped when its number is missing. Page cached 1 h (on demand ISR; a request before the threshold is met caches a 404 for up to an hour). `/jobs` and the sitemap are dynamic with a 5 minute in process cache. Individual job URLs are not in the sitemap (too many for one file; add a sitemap index in M5 if wanted).
- **D-036 Job page SEO:** open jobs are now indexable with a canonical and JobPosting JSON-LD (`url` = employer apply page, `datePosted` = the company's own date, `directApply: false`, remote jobs as TELECOMMUTE). Closed jobs are noindex and emit no JSON-LD.
- **D-037 Placeholders:** a test scans `src/` for `{{name}}` patterns and fails if one is missing from `docs/MANUAL_STEPS.md` (item 9).

## M5 pre-launch review (5 Nov 2026)
- **D-038 Refund rule stays as built, and the policy now says so:** one refund per Stripe customer, for the newest charge if it is at most 7 days old, self serve in Account or by email, and it ends the plan right away. The brief says "if first charge <=7 days old". This is more generous and bounded at one, so it stays. The refund policy and the help page were rewritten to match (the old text promised a refund on every payment). Owner can narrow it to the first charge later (REVIEW P1-3).
- **D-039 Plans not on sale:** `Plan.onSale` is false for Plus until the resume match check, the cover letter outline and the 15 minute re-checks exist. Checkout refuses it (409 `plan_not_on_sale`), the paywall leaves it out, and the pricing page shows it as "Not on sale yet" with no buy link. Prices and lookup keys stay in `product.ts`, so turning it on is a one-line change once the features ship. Monthly's highlights dropped "Application tracker" and "Follow companies" (not built).
- **D-040 One paid plan at a time:** Checkout refuses Lifetime while a subscription for this app is live, and refuses any purchase while Lifetime is held. Upgrading from a subscription to Lifetime means cancelling first. A one-tap upgrade that cancels the subscription in the same flow can come later.
- **D-041 JSON-LD `url`:** JobPosting `url` is our own job page, never the employer's apply link (that link is what a metered open unlocks). Supersedes the `url` part of D-036.
- **D-042 Crawl redirects:** the transport never follows redirects. `fetchPolite` follows up to 5, and each hop goes through egress rules, the target host's robots.txt and its rate limit.
- **D-043 Hero subhead:** "thousands of" is dropped from the brief's subhead until `/admin/crawl` shows that many active boards.

## REVIEW P1 fixes (6 Nov 2026)
- **D-044 Refund rule follows the brief (supersedes D-038):** only the customer's first successful charge for this app is refundable, and only within 7 days of it. Once per Stripe customer and per billing email (lowercased, kept as a base64url sha256 of `app:email` in `refunds`, so it outlives account deletion and holds nothing readable). Admins can still waive the window. Known edge: a Lifetime buyer whose first charge was an older Weekly payment gets no self-serve refund (MANUAL_STEPS 14).
- **D-045 Disputes:** an open dispute switches the plan off whatever it was (subscription or Lifetime) and holds it off against later events and refreshes. Won restores it, lost keeps it off, cancels subscriptions and frees a Lifetime slot. Dispute records are kept after account deletion as a fraud trail. Needs the two dispute events on the Stripe webhook endpoint (MANUAL_STEPS 16).
- **D-046 Annual reminder:** 21 days before renewal (California asks for 15 to 45), once per renewal date. Weekly and monthly stay at 3 days.
- **D-047 Unsubscribe:** GET never writes. The confirm button POSTs with `confirm=1`; the RFC 8058 one-click POST is unchanged.
- **D-048 Accessibility gate:** `tests/e2e/a11y.spec.ts` runs axe-core (already installed, no new dependency) on seven pages at 375 px in both themes and fails on serious or critical findings.
- **D-049 Auto indexes:** the Mongo driver runs `ensureIndexes` once per instance in the background after the first connection (skipped in `next build` and for the memory driver, never awaited, conflicts and errors logged scrubbed). `npm run db:indexes` still works and throws on errors.
- **D-050 Mail never fails silently in production:** `transportFromEnv` used to fall back to the console outbox when `MAIL_PROVIDER=resend` had a missing or blank `RESEND_API_KEY` (sign-in still answered "check your inbox"; only an info line `mail_console` was logged). In production that is now a transport that fails every send with reason `resend_api_key_missing`; the key is trimmed; a console send in production throws `console_transport` (except the documented stub mode `MAIL_CONSOLE_PRINT=1`, which still logs at error, and the e2e server with `E2E_OUTBOX=1`). `sendAuthMail` logs failures and skips at **error** with `reason`, provider `status` and Resend's error `name` only (never the address, link or provider message), logs `auth_mail_sent` (provider + message id) at info on success, and the HTTP answer stays `{status:true}`.
- **D-051 Honest cadence on Vercel Hobby:** production runs each scheduled job once a day, 60 s per run. `CADENCE` and `cadence` in `src/config/product.ts` drive every public sentence about how often (hero, FAQ, /how-we-check, docs, alerts pages, plan highlights); `tests/unit/cadence.test.ts` fails if copy makes a fast claim or stops reading the constant. `crawl-tick` loops leased shards for about 40 s, then runs source health and retention; `webhook-retries` then runs digest, alerts and renewal reminders (each step isolated). Free digest goes out in the one daily run for all time zones; paid "instant alerts" became "saved alerts" emailing new matches once a day. Boards are due again after 20 h (not 24) so Hobby cron drift never skips a day. Ashby seeds are `disabled` with the robots.txt reason (existing rows are switched off on the next seed run unless an admin re-enabled them).
